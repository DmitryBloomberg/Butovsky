# Butovsky
Официальный сайт Butovsky.

## Деплой на Linux-сервер

Распакуйте архив, перейдите в папку `Butovsky` и выполните:

```bash
bash start.sh
```

При первом запуске скрипт попросит домен и сохранит его в локальном файле
`.deploy.env`. Затем Docker Compose соберёт контейнер сайта и запустит Caddy.
Caddy автоматически запросит и будет продлевать HTTPS-сертификат Let's Encrypt.
Сайт откроется по адресу `https://ваш-домен:8443`; HTTP-запросы на порт 80
перенаправляются на этот адрес.

### Перед запуском

- На сервере должны быть установлены Docker Engine, Compose v2 и `ss`
  (обычно входит в пакет `iproute2`).
- A/AAAA-запись домена должна указывать на этот сервер.
- Внешний firewall или панель хостинга должны пропускать входящие TCP-порты
  80 и 8443.

### Изоляция и безопасность

- Скрипт не устанавливает системные пакеты, не меняет firewall и конфигурацию
  системного Nginx, не останавливает и не удаляет чужие контейнеры.
- Порт 443 не используется: он остаётся за Remnawave. Если порт 80 или 8443
  занят, скрипт завершится до запуска Compose и сообщит
  причину. Освободите порты или настройте существующий reverse proxy вручную.
- Веб-контейнер не публикует порт 3000 на сервере. Сайт доступен через отдельный
  Caddy-контейнер этого проекта на портах 80 и 8443.
- Docker Compose получает уникальное имя проекта из пути к этой папке; он
  управляет только контейнерами, сетью и томами этого проекта.
- Используется готовая папка `build`, поэтому Node.js и npm на сервере не нужны.
  Docker и Compose проверяются перед запуском; отсутствующие системные пакеты
  скрипт не устанавливает автоматически.

Проверить состояние и логи этого проекта:

```bash
bash start.sh status
bash start.sh logs
```

Чтобы остановить только этот сайт, не удаляя его сертификаты и тома:

```bash
bash start.sh stop
```

Не запускайте глобальную очистку Docker (`docker system prune`) на общем сервере.
